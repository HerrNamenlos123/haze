# haze-notes vault tree order

Folders first, then dated names oldest first, then the rest by numeric German collation; ties keep byte order.

Verified 2026-11-04 against d35a505e. (comparator located in haze-notes/src/vault.hz; the verification figures are from 2026-10-15)

Order (`compareVaultOrder` in haze-notes/src/vault.hz, mirroring the web app technicalsketcher.web's `compareEntries`):
1. Folders first.
2. Names starting with `^\d{2}[-.]\d{2}[-.]\d{4}` by JS `new Date(y, m-1, d)` day (rollover; month 00; years 0-99 = 19xx).
3. Dated names before undated ones.
4. The rest by `localeCompare("de", {numeric:true})` (here `unicode.collationKey(name, { numeric: true })`, stdlib/unicode haze_collation.c).

The reference comparator returns 0 for equal dates and for names that collate equal ("a01"/"a1"); its stable sort then keeps readdir order, which Node/libuv sorts by strcmp on Linux. So both ties go by byte order (`compareBytes`); equal dates do NOT use the name collation.

Test: haze-notes/tests/vault-order-tests.hz, whose expected order was generated by the reference comparator's own code on the same fixture. Oracle technique: Electron's Node (ICU 78.2) via `ELECTRON_RUN_AS_NODE=1` runs the real comparator, sliced out of the web app's store.ts and type-stripped with esbuild.

ICU findings: ICU 77 (Node 22) orders CJK ideographs across blocks differently from ICU 78 (78 matches UCA implicit weights). ICU 78 numeric mode has a quirk with supplementary-plane digits after an identical prefix (it backs up over BMP digits but stops at a lead surrogate). Discontiguous contractions are not implemented in Haze's collation (2 in 100k contraction-heavy pairs). The Haze JSON reader truncates strings at `\u0000`, so keep NUL out of oracle inputs.
