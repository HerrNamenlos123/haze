# Pen and touch pointer model (sdl -> app -> ui_components)

Device-typed PointerEdges from SDL pen/touch events, implicit capture, primary-pointer rules and the pen button mapping.

Verified 2026-11-04 against d35a505e. (symbols and files checked; Wayland eraser patch listed in the original no longer exists, see below)

- **stdlib/sdl/src/sdl_impl.c**: one `pointer` trampoline for pen and touch: (kind 0 down / 1 up / 2 move / 3 cancel, device 1 pen / 2 touch, id, x, y, pressure, DOM `buttons` bits 1 tip/finger, 2 barrel1, 4 barrel2, 32 eraser). Pressure comes only from SDL_EVENT_PEN_AXIS, cached per pen. Touch x/y are normalized in SDL and scaled by the window size. SDL's synthesized mouse events (`SDL_PEN_MOUSEID`/`SDL_TOUCH_MOUSEID`) and pen-as-touch (`SDL_PEN_TOUCHID`) are dropped at poll time, AFTER the titlebar handler sees them. `haze_sdl_pen_button_bit` maps SDL pen buttons to DOM bits per platform: on Linux SDL pen button 2 (BTN_STYLUS2) is the right click and 1 (BTN_STYLUS) the middle, with the desktop's default stylus setting delivering the lower barrel as 2; on Windows/macOS SDL 1 is the barrel.
- **stdlib/app/src/app.hz**: `PointerEdge` has `pointerId` (mouse 1, pen 1000+id, touch 100000+id), `pointerType`, `buttons`, `pressure`, `isPrimary`, kinds Moved/Cancelled. Mouse moves are queued too (consecutive ones coalesce); pen/touch moves are per sample. Pen and the FIRST finger also drive `mousePosition` and the `leftHeld` level (OR of mouse/pen tip/touch). `PointerEdge` is a value struct in both `app` and `ui_components` (it was a ref struct: two heap objects, 160 GC bytes per pen sample, since 5af4b49c 0); the queues keep their buffers and `App.queueMouseMove` writes the coalesced edge back with whole-element assignment because `last` is a copy. `KeyEdge` stays a `ref struct`. `PointerEvent`, like every ui_components event, is a value since 2026-11-12: `stopPropagation()` reaches the other handlers through a shared flag slot, see [[ui-event-dispatch]].
- **ui_components**: pen/touch get implicit capture (`_pointerCaptures`); mouse does not (widgets poll `ui.leftMouseHeld()` for drags). Click/focus/dismiss/contextmenu only for `isPrimary`; Cancelled = Up without click. `PointerHeldCallbacks.reportsMotion` (explicit, default false) says the host queues every move; otherwise one Move per frame is synthesized from the polled position. `PointerButtons` has Back/Forward/Eraser (8/16/32), `pointerButtonsFromBits(int)`, `PointerButton.Eraser`.
- Barrel = right button: a pen tip touching down with the barrel bit (2) held is a `button: 2` (Right) press and its release reports the same button even if the barrel was let go mid-contact (`app.PenContacts`; the eraser wins as 5). It fires `contextmenu` like a right click and never clicks. A barrel pressed while hovering is only a move. Canvas code reads `e.buttons`, never `e.button`, for pens.
- SDL 3.2.8 handed out a new pen id on every proximity-in, so per-pen-id state must not grow per id (PenContacts keeps only pens in contact). The SDL Wayland backend always reported `eraser=false`; the repo previously carried a `wayland-pen-eraser.patch` for it (removed in commit 602466d1; the pin is now release-3.4.18, check upstream before re-adding).
- Pen on the libdecor titlebar: PEN_DOWN with window NULL and no motion (x=0,y=0), dropped in `haze_sdl_dispatch_pointer`.
- Hosts translating app edges to UI edges: haze-notes/src/main.hz and codeeditor/src/main.hz (`toUIPointerEdges`), both with `reportsMotion: true`.
- Diagnosis technique: a tiny SDL3 C logger linked against `__haze__/sdl/bin/lib64/libSDL3.a` (+ -lwayland-client) while a person performs the gestures; uinput virtual pens are opened by Mutter but never reach any client.
- Tests: stdlib/ui_components/tests/pen-touch-tests.hz and stdlib/app/tests/pen-contacts-tests.hz (see [[running-stdlib-module-tests]]).
