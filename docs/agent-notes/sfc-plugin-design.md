# hzui SFC format and the compiler plugin interface

Vue-like single-file components (`.hzui`) compiled by a plugin of the Haze compiler; the compiler core contains nothing UI-specific.

Verified 2026-11-04 against d35a505e. (interface, hooks and docs checked; locked decisions are recorded in docs/sfc-plugin-scope.md, the normative source, and this note only maps where to look)

- Design and decision log: docs/sfc-plugin-scope.md; normative lowering example: stdlib/hzui/plugin/fixtures/button.expected.hz.
- Compiler side: `[plugins] hzui = { path = ... }` in haze.toml (dependency-style, non-inheriting: each module with `.hzui` files declares it); generic interface in src/Plugins/PluginInterface.ts (PluginHost, structural TransformPlugin contract, dynamic import of `<path>/plugin/index.ts`); hook `ModuleCompiler.transformWithPlugins` between readFile and parse (collectFile / collectFileAsRoot); plugins register `extensions`, which the compiler collects like `.hz`. Plugin errors are one generic code plus name and message. Known gap: transform output is not in cache keys (`TODO(plugin-cache)` in ModuleCompiler.ts), so plugin or config edits do not invalidate cached ASTs.
- Source mapping uses `#source` pragmas in both parsers: pin mode (span) and offset mode (`"file:line"`, a C #line-style line map) at global, struct and statement positions (src/Parser/Parser.ts); relative paths resolve against the parsed file; the transformer emits basenames.
- Plugin side (stdlib/hzui/plugin/): sections, classlist, template, compose, index; golden tests via `bun test stdlib/hzui/plugin/transform.test.ts` (`UPDATE_GOLDEN=1` regenerates). Transformed output is dumped to `__haze__/<module>/build/transformed/<src-relative>.hz`. VS Code grammar-only extension: stdlib/hzui/vscode.
- Format rules: declaration sections in any order, then `@setup`, then `@template`; every template value, condition or content is a single identifier, string, number or `[expr]` (member access must be bracketed: `[props.x]?token`, `label=[props.x]`); the first `[ ]` after a tag is the class list, a later one is content; ids are auto-sequential per enclosing scope; `key=` is mandatory on all direct loop children; `computed`/`elementRef` are forwarded by textual rewrite (Haze has no generic function values).
- Styling runtime: ops merge last-wins per field (explicit style overlaid after); per-side `PaddingOp` with Length (Px|Em|Rem, rootFontSize 16) fields.
- Compiler quirks met: `x is not none` on an ALIAS-typed union fails ("union comparison on a non-union"): use `!(x is none)`. `emit` is an unintended reserved token (`EMIT` in HazeLexer.g4), so it cannot be used as an identifier. `for comptime field in T.fields` works (stdlib/core/src/reactive.hz). Biome enforces braces-always and no shorthand object properties. The installed `haze` binary can be stale; test compiler changes with `bun run src/main.ts`.
