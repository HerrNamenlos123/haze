# Haze language and stdlib gotchas (verified subset)

Language quirks and stdlib facts that were re-checked against the current tree; the rest of the original collection is not carried here because it was not re-verified.

Verified 2026-11-04 against d35a505e.

- Reserved words that cannot be identifiers: `from`, `plain`, `emit` (`src/Parser/grammar/HazeLexer.g4`), and `export`. The parse error for a reserved word is often an unhelpful "no viable alternative at input" covering the whole enclosing function.
- An f-string inside an f-string's `{}` (`f"{g(f\"{x}\")}"`) does not parse: H1000 "Unexpected character" at the inner `f`. Bind the inner string to a variable first. (Verified 2026-11-04 against 3165b22f.)
- A plain `const` used as a struct field default fails with H3002 "Symbol ... was not declared in this scope" at the struct; `const comptime` works there. (Verified 2026-11-04 against 3165b22f.)
- `break` and `continue` exist (lexer tokens `BREAK`, `CONTINUE`). Older advice to emulate them with `return` is stale.
- `math.min` / `math.max` are generic `fn`s inside `namespace math` but NOT exported (`stdlib/core/src/math.hz`), so `math.min(...)` does not resolve from another package. `renderer.gfx` uses a local `max<T>`.
- `sys.exit()` does not exist; use `sys.panic(msg)` (`stdlib/core/src/system.hz`) or a return code. Command-line args: [[feedback-args-global-utf8]].
- A namespace used as a value type is rejected with H7214 (`rejectNamespaceAsValueType`, `src/Semantic/LookupDatatype.ts`; `testsuite/src/cases_namespace_as_type.hz`). Namespaces as generic ARGS stay legal.
- `json.parse<T>` fills an absent key from the field's declared default, the same expression a struct literal uses (reflection `T.hasFieldDefault(name)` / `T.fieldDefault(name)`, H7215; `testsuite/src/cases_json_field_defaults.hz`). So cache/config structs should say `x: []str = []`, not `x: []str | none = none`.
- `json.parse<T>` reads only the keys T has fields for and drops every other key silently (`parseJsonStruct` in `stdlib/core/src/json.hz` loops over `T.fields`), and it matches keys case-insensitively, taking the first match (`hzstd_json_get_object_item`, `stdlib/core/src/hzstd/src/json/hzstd_json.c:159`). So parse then stringify is not a lossless roundtrip: proving a conversion lost nothing needs a comparison against the original `json.Node` tree. (Verified 2026-11-10 against bf4a25f5.)
- Struct `==` is autogenerated memberwise and recursive (`testsuite/src/cases_value_equality.hz`); a struct declaring only one of `operator==` / `operator!=` has only that one.
- Lambdas always elaborate fresh: `callableExpr()` passes `{ bypassCache: true }` to `elaborateFunctionSymbol()` (`src/Semantic/Elaborate.ts`), because the function-definition cache key does not distinguish two lambda literals at the same source location (a `for comptime` loop body is elaborated N times). Fixed-size arrays `[N]T` work, `N` any comptime constant (`testsuite/src/cases_static_arrays.hz`, `createStaticArray` in `stdlib/core/src/util.hz`).
- Iterating a reactive array: `for x in arr` directly; never `rx.get(arr)` first (`testsuite/src/cases_foreach_reactive.hz`).
- If-chain narrowing rule: after an if / else-if chain only the conditions of the branches BEFORE the first one that falls through are known false (`testsuite/src/cases_if_chain_narrowing.hz`).
- Single-line text inputs must normalize newlines on READ (`withoutLineBreaks` and the `line` computed in `stdlib/ui_widgets/src/TextInput.hzui`).
- Regression tests live in `testsuite/src/cases_*.hz`, see [[feedback-tdd-loop-for-compiler-bugs]].
