# Arenas, scanned and unscanned memory

How hzstd arenas are built (two chunk chains, chunk policies, measuring, labels), what "unscanned" memory is, and the traps around it.

Verified 2026-11-11 against 027833aa plus the uncommitted arena change (cases_arena.hz, cases_fs_list_dir.hz, cases_stdin.hz).

- **Words.** Scanned memory is searched by the GC for pointers; unscanned memory (BDWGC "atomic", `GC_malloc_atomic`) never is, and is NOT zeroed. C API: `allocate` / `allocateUnscanned` on `hzstd_allocator_t`, `hzstd_allocate_unscanned`, `hzstd_heap_allocate_unscanned`, `hzstd_arena_allocate_unscanned` (hzstd_types.h, hzstd_memory.h). The word "atomic" is gone from hzstd's API.
- **Invariant:** unscanned memory holds plain bytes only. A pointer to GC memory stored there does not keep its target alive (cases_arena "unscanned memory keeps nothing alive" shows the collector freeing it). Haze code cannot reach unscanned allocation: `Allocator` is opaque, and only stdlib str/Bytes/ByteBuffer code (and C) asks for it. Every string the stdlib makes is a pointer-free block (checked per source with `GC_get_kind_and_size` in cases_arena).
- **Two chains.** BDWGC cannot exempt a range inside one block, so `hzstd_arena_t` has a scanned and an unscanned chain (hzstd_memory.c, "Arenas"). Each chain is made at its first allocation. Chunk headers (`hzstd_arena_chunk_t`) are always scanned memory: the first per chain is inline in `hzstd_arena_t`, later scanned chunks carry the header in their own block, later unscanned chunks get a separate small scanned header block. A header inside an unscanned block would let the GC free later chunks of a live arena.
- **Lifetime.** `GC_all_interior_pointers` is on in the BDWGC build the compiler links (`~/.haze/global/haze-bdwgc`, checked with `GC_get_all_interior_pointers()`), so a str viewing the middle of a chunk keeps that chunk (not the arena) alive. An arena is never locked: one thread at a time.
- **Chunk policy** (`ChunkPolicy` in memory.hz, `hzstd_arena_chunk_policy_t`): chunk 1 = firstBytes, 2 = nextBytes, later = min(previous * growth, maxBytes); growth 1.0 keeps nextBytes and ignores maxBytes. An allocation bigger than the next regular chunk gets a dedicated exact chunk that is not the bump target and does not advance the sizes. First allocation bigger than firstBytes: the first chunk is that size. Defaults 1024 / 2048 / 2.0 / 65536 exist twice (ChunkPolicy field defaults and `HZSTD_ARENA_DEFAULT_*`); cases_arena compares them. Bad policies panic at creation.
- **Alignment:** both chains align to `alignof(max_align_t)` (16): unscanned memory also holds Bytes that C may read as typed data. A 13-byte name costs 16 bytes.
- **The Arena type:** `Alloc.arena(options)` returns an `Arena` (memory.hz), a value struct holding only the allocator handle (a copy is the same arena). It passes as an `Allocator` through `operator as`, also into generic overloads such as `json.parse<T>(allocator, data)`; both needed compiler fixes made with it (see [[order-dependent-struct-method-elaboration]] and the implicit overload tier in Elaborate.ts, cases_operator_as.hz).
- **Measure / presize:** `arena.measure()` returns per chain the sum of allocation sizes rounded to 16, a counter (O(1)), equal to what one chunk needs for the same allocations. `ArenaOptions.sizedFor(usage, spare = 0.01)` sets each used chain's firstBytes to that plus spare. An `Arena` literal around a non-arena allocator panics when measured (`hzstd_allocator_is_arena` compares the allocate function pointer).
- **Labels:** `ArenaOptions.label` is `ccstr`, so only a literal compiles (the profiler stores the pointer). Trace kinds (profiling.hz `allocationKindName`): 3 "Arena" (dataType = label), 5 "Arena chunk (scanned)", 6 "Arena chunk (unscanned)". Each chunk is one event: the blocks are taken with `GC_malloc*` directly, not through `hzstd_heap_allocate`, which used to report every chunk a second time. C callers pass `HZSTD_ARENA_OPTIONS("label")`.
- **Users:** fs.listDir (one arena per call, 512 B first chunk, label "fs.listDir names", or the caller's arena via `listDir(allocator, path)`), `DirEntry.path(allocator)`, haze-notes vault index (`indexVault` sizes its arena from `VaultCache.indexArena`, the last measurement), codeeditor quick open (one arena per scan).
- **Trap:** cJSON allocates node and string memory through one hook (hzstd_json.c `hzstd_json_alloc`), so json strings in an arena are scanned.
- **Trap:** a test program's own C has no `<stdio.h>` unless it includes it; `<gc/gc.h>` works from a test program (`#define GC_THREADS` first).
