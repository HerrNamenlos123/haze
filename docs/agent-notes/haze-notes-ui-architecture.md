# haze-notes UI architecture

Theme tokens, component list, the flat virtualized FileTree, keyed Workspace per vault, vault index and caches, sidebar persistence, screenshot recipe.

Verified 2026-11-04 against d35a505e (symbols checked; numbers are from the 2026-10-15 build); the index, cache and tree-scroll lines re-checked 2026-11-11 against d341d7f0 plus the uncommitted startup work.

- Theme (`theme.hz`): `struct Theme` of semantic role tokens; ONE palette `appTheme()` (charcoal chrome #2E2F33, desk #4D4E53, surface #393A3F, amber accent), read via `theme()`. Components write `bg-[theme().chrome]`, never colours. No theme switch, no light theme. Pages get an on-screen shadow (`render.hz` `drawPageShadow`).
- Components: UI (root, vault sessions) to AppBar (+WindowControls) / WelcomeScreen (+RecentVaultRow) / Workspace to Sidebar (+FileTree to FileTreeRow, EmptyState) + Splitter overlay + DocumentView (+Toolbar, SelectionToolbar, PenMenu, Surface, ColorSwatch, PenSizeButton, Divider, ProgressBar). IconButton is the app's own button.
- FileTree is a flat virtualized list (`filetree.hz`: flattenTree / treeWindow / folderChainTo over a `VaultIndex`; tests in `haze-notes/tests/filetree-tests.hz`, including flattenTree against a naive filter for every open/closed combination). Rows are keyed by WINDOW SLOT (`key=[i]` in `FileTree.hzui`), not list position: the vendored Clay 0.13 never frees its 8192-entry element-id map, so position keys ran it full after ~790 rows scrolled past and the tree went blank (upstream prunes it in Clay_EndLayout; our fork has local patches: idAlias, CSS translate). Rows are exactly 28 px with no margin (a margin made scroll height depend on the window and flickered). A pre-watch on the exact content height calls `scroll.setMetrics` so a shrink clamps before the frame.
- Vault index (`vault.hz`): technicalsketcher.web's readVault rules: files whose name ends in `noteExtension` = ".hznote" (dot-files included; until 2026-11-11 technicalsketcher.web's rule, names CONTAINING ".tsk"), folders not starting with ".", empty folders pruned, in tsk's order (`compareVaultOrder`; in-place `array.sort` exists, do not add another sort).
- `VaultIndex` is flat: `entries` = Bytes of `count` plain `IndexEntry` records (7 u32, 28 bytes: path start/length in `text`, name length, depth, folder, ghost, descendants), preorder; `text` = the vault-relative paths ("/" between parts). A closed folder is skipped by `descendants`. Paths are vault-relative everywhere in Workspace/Sidebar/FileTree; `vaultAbsolute` / `vaultRelative` convert at the file system (`onDisk` in Workspace).
- `VaultWalk` builds it (one `fs.listDir` per `stepOnce`; `step(deadline)` or `run()`); `index(ghosts)` allocates entries and text once each, exactly sized, in the walk's arena ([[arenas-scanned-unscanned]]).
- Caches (`UI.hzui`, binary `CacheFile`, [[binfile-and-cachefile]]): `app.hzcache` (GlobalCache) in `$XDG_CACHE_HOME`, else `$HOME/.cache`, else `%LOCALAPPDATA%`, plus `/haze-notes/`; per vault `.hznotes/vault.hzcache` (VaultCache: last note, open folders, sidebar, show-all, `treeScrollTop`) and `.hznotes/index.hzcache` (IndexCache: the index, the walk's arena measurement; its own file so it is written only when the index changes). Loaded as views, so frame 0 has the index.
- Workspace walks the vault at setup only when the cache has no index; otherwise once, in the background, after the note is loaded and `DocumentRenderer.hasPendingWork()` is false, 2 ms per frame (`INDEX_WALK_STEP_SECONDS`), applied only when `sameAs` says it changed. Any walk in the Workspace (refresh after create/delete/keep) counts as that one.
- The tree is not scrolled to the open note on mount: it starts at `VaultCache.treeScrollTop` (ScrollView's `initialScrollTop`, written into the cell at mount and clamped only once measured) and writes the position back every frame it changes (the cache writes it to disk once settled). `reveal` / `revealSerial` still scroll a created entry into view.
- Sessions: `Workspace for=[s in sessions] key=[s.id]`; the same dir keeps the same session. Replaced sessions get `VaultSession.close()` (both caches written and unwatched; all caches also at `onExit`). The note's EditorControls come from `noteEditor(ui, gfx, canvasRef)` (`editor.hz`), shared by Workspace and ExclusiveNote: it registers the save/export at `onExit` and at the component's `onUnmount` (which also releases GPU resources and disarms the `onExit`).
- Sidebar: width/open in `VaultCache` (`sidepanelWidth` px, `sidepanelOpen`), width committed on Splitter's `end` emit, hidden (not unmounted) when collapsed, Ctrl+B. Keys are handled at the Workspace root (focusable).
- Command line (`cli.hz`, verified 2026-11-20 against a9f18445 plus the uncommitted CLI work): `haze-notes <note>` resolves the path with `fs.realPath`, takes as vault the nearest folder above it holding `.hznotes/`, refuses a note in none (exit 1), then UI.hzui's `startVault`/`startNote` props call `openVault` and write the session's `lastOpenedFile`, and `VaultSession.reveal` is handed to Workspace's `revealOnMount`, which FileTree reveals at mount (its revealSerial watch is immediate). `haze-notes --exclusive <note>` mounts `ExclusiveNote.hzui` instead of UI.hzui with `rememberWindowState: false`: no GlobalCache, VaultCache, IndexCache or `.hznotes` touched. `new` and `export-pdf` return from `main` before the paper decode and `app.App`, so they need no display: `new` builds `newNote()` (persistence.hz, shared with the tree's New note), adds an `--image` as an ImageShape (PNG kept, other formats converted with image.encodePng) at x 0, y 0, full page width or shrunk to page height, and creates the file through `createNote` (never replaces); `export-pdf` runs `DocumentLoad` then `PdfExport.finish()`, output by default `pdfPathFor(note)`; of a note open in a window it exports the last autosave (product decision 2026-11-20).
- Trap: a `ref struct` in a haze-notes .hz file holding `EditorControls` and a `CanvasRef` made the build fail with H7015 (json.serialize of `LinearMap<Bytes, gfx.Texture>`, reported in `__haze__/haze-stdlib/build/import.hz` with no trace into user code); returning the EditorControls alone builds. Mechanism not traced.
- Screenshot sandbox: run the built binary with `XDG_CACHE_HOME=<scratch>/cache SDL_VIDEODRIVER=x11` and a scratch vault, never a real cache/vault (an exiting instance saves the open note).
