# Vim / textedit engine: architecture, test harness, neovim facts

stdlib/textedit_behavior is a general editing engine; stdlib/vim_behavior is an optional behavior on top; both are validated differentially against real headless neovim.

Verified 2026-11-04 against d35a505e. (scripts, modules and hook names exist; gate counts are from 2026-08 and the suites should be re-run to see the current numbers)

- Architecture: `textedit_behavior` (text, selections, motions, transactions, undo, modes) and `vim_behavior` (modes, keymaps, operators, counts, registers) render nothing; a behavior is installed with `ctx.setBehavior(...)`, without one the engine is a plain textbox. See stdlib/vim_behavior/README.md. codeeditor toggles vim at runtime (`vimOn` in EditorView.hzui), swapping only the behavior (document, caret and undo history survive); `vim_behavior.defaultVimrc()` is the vimrc.
- Syntax highlighting is incremental: codeeditor/syntax-engine/syntax-engine.ts keeps a per-line TextMate rule-stack cache, takes `open`/`change` (`change` = `text_document.ChangeSet`: startLine/removedCount/newLines), retokenizes from the edited line and stops once the rule stack reconverges (an opened block comment still cascades to EOF). Replies are MERGED per line (`mergeHighlightResult`), not used to replace the cache. Gate: `bun run scripts/syntax-incremental-test.ts` (randomized edits must produce byte-identical tokens to a full reparse).
- The document is `stdlib/text_document.Document` (`mut []String` lines mutated in place, O(edit)); rendering culls to `scroll.visibleRange(...)` and syntax tokens are bucketed per line (the quadratic freeze was rescanning all tokens per line).
- Tests, all differential against neovim (oracle: vimtest/oracle/, ORACLE.md): `bun run scripts/vim-core-cases.ts [--remaps]` (supported subset, regression gate), `scripts/vim-jumplist-cases.ts`, `scripts/vim-comment-cases.ts`, `scripts/vim-difftest.ts --seed N --count N` (random fuzz; ~92% agreement, the rest a diffuse tail of one-off edge cases, mostly `>`/`<` cursor placement) or `--keys "d2w" --lines "a b c" --col 0` for one case.
- Neovim facts that cost debugging time: `cpoptions` must include `_` or `cw` stops behaving like `ce` (an oracle hardcoding a default string changes `cw`); neovim has `startofline` OFF (`G`, `gg`, `dd`, `<C-d>` keep the column) and `autoindent` ON; visual mode lets the caret sit one past the last character, normal mode does not; `de` across lines is linewise (regtype V) while `ye`/`ce` on the same range are charwise (promotion is delete-only for inclusive motions); count overflow: `dd`/`yy` clamp, `cc`/`C` fail; `p` in visual mode swaps the register, `P` does not (the reason for `vnoremap p P`); since neovim 0.10 `Y` is `y$` and `gc`/`gcc` exist by default (an oracle that wipes all mappings loses them; it must snapshot defaults and restore them).
- Not implemented deliberately: macros, named registers, marks, search `/`+`n`, visual block, `gu`/`gU`; ex commands only as the host hook (`onExCommand`: `w q wq x e`, `a`/`all`, `!`).
- The jump list is NOT a browser history: Vim's `setpcmark()` only appends and parks the index at the end (no forward truncation); `cleanup_jumplist()` removes entries whose LINE recurs later, keeping the newest (after `5G 10G <C-o> 15G` vim holds `[1,10,5]`); cap 100; the entry for the line the cursor is on is removed when the index is at the end; `<C-o>` is inert in visual mode; off-the-end is a no-op. The oracle's `clearjumps` must run per WINDOW (after `nvim_win_set_buf`).
- Commenting follows neovim's runtime/lua/vim/_comment.lua: one `commentstring` template (`"// %s"`, `"<!-- %s -->"`), padding part of the template; uncomment only when EVERY non-blank line is commented; marker at the range's smallest indent; blank lines ignored for both decisions but still commented; an all-blank range is untouched.
- A count means two things to `>`/`<`: `3>>` in normal mode indents three lines by one level; `3>` in visual mode indents the selection by three levels (one undo step). Dedent removes one level at a time.
- Vertical moves must use `desiredColumn()` (curswant): vim clamps what it displays but keeps the wanted column. `gd` calls the host hook `Vim.onGoToDefinition`, wired to tsserver's `definition` (not the LSP: vue-language-server runs hybrid with no semantic TS service, and tsserver replies with plain absolute paths).
- Supported vimrc subset: `inoremap jk <Esc>`, `nnoremap j jzz` / `k kzz`, `nnoremap <space>aa ggVG`, `vnoremap p P`, `nnoremap <C-d>/<C-u>/<C-o> + zz`, `nnoremap n nzzzv` / `N Nzzzv`, `set clipboard=unnamedplus`.
