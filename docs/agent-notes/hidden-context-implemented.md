# The hidden context as built

`context`, `Context()`, `context.clone`, extern C functions with a Haze body, `:: context`, `sys.contextPtr()`, and the `__hz_ctx` ABI. Normative description: DEVELOPMENT.md, section "The hidden context (calling convention)"; the design is Axiom C209, C390 to C406, C468 to C477, C500 to C510, C567 to C569 and `docs/async-runtime.md` section 3.

Verified 2026-11-18 against the stage 1 commit on branch async-runtime.

- C: `hzstd_context_t { task, thread, settings }` (`hzstd_types.h`); `hzstd_context_settings_t { allocator, logger, userBox1, userBox2 }`. Haze `context` is `(*__hz_ctx).settings`, type `Context` = the opaque extern C struct `hzstd_context_settings_t` (`stdlib/core/src/context.hz`): reads copy the settings, writes go through, `Context {}` is rejected (H7118).
- `Context()` is `hzstd_context_settings_default()`. `context.clone(b)` copies the whole context (same task and thread) into a stack local and calls `b` with its address: no allocation (`cases_context.hz` checks it with the profiler).
- `extern C fn f(...) { body }` takes `hzstd_context_t *` first and has `context`; its type is a Haze function type. `extern C fn f(...): R :: final;` is a C function (no context). `:: context` on a body-less `extern C` declaration makes it take the context; Export.ts writes it for Haze-bodied ones, since interfaces carry no bodies (without it an importer called them without a context: a crash). `isCFunction` (Elaborate.ts) decides; H7233 rejects `:: context` elsewhere (also with a body); structs and enums take no requirements (syntax error, both parsers).
- Default parameter values are evaluated by the caller: `context` in one is the caller's. A body-less declaration (a module interface, a C entry) elaborates its signature in `Collect.FunctionSymbol.signatureScope`, a scope holding only `context`.
- `Logger` and `Allocator` are opaque like `Context` (a zero one holds NULL function pointers, C399); `json.parse` and `traverse.readStruct` static-assert on all three.
- Runtime: the main thread and its task are statics set up in `hzstd_initialize_main_thread` (id 1); `hzstd_context_for_current_thread()` reads the one `_Thread_local` (`hzstd_current_thread`) and panics on a thread Haze does not manage (C505; tested by a program that re-runs itself and starts a raw pthread).
- `sys.contextPtr()` is the one inline-C use of `__hz_ctx`; `sys.threadId()`, `sys.log`, `sys.makeUserBox<T>`, `sys.userBoxValue<T>` (give `T` explicitly for literals: `makeUserBox(7)` deduces the literal type `const 7`).
- Removed: `Context.init`, H7219, H7220, `checkExternCBodyNeedsNoContext`. Modules outside stdlib/core that used `Context.init` (sdl, ui_layout, wgpu, single_instance, language_server_protocol, tests/stdlib-paths/headless) do not compile until migrated.
