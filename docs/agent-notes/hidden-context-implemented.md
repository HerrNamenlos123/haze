# The hidden context as built

`context`, `Context()`, `context.clone`, `Context.init`, `extern C (...) -> R` and the `__hz_ctx` ABI. Normative description: DEVELOPMENT.md, section "The hidden context (calling convention)".

Verified 2026-11-04 against d35a505e. (error-code sites, intrinsics and tests checked; per-bullet runtime behaviour taken from the build notes)

- `context` is an implicit variable in every Haze fn, `=>` lambda and `->` literal, and none in `extern C` fns (H7219, `src/Semantic/Elaborate.ts`). Value type `Context` (alias of opaque `hzstd_context_t`); reads copy, `context = c` and member writes go through. `let stackref r = context` is H7221. Haze has no `&` operator (`&x` is H1000; address-of is the `addressOf()` library fn).
- Any bare-name declaration named `context` is H7222 (locals, globals, params of fns with a body, lambda params, loop vars, free fns, types, namespaces, generics, imports). Fields and methods are fine.
- `Context()` calls the extern C `ffi.hzstd_context_default` (`stdlib/core/src/context.hz`). `context.clone(b)` / `Context.init(v, b)` become `ContextScopeExpr` (Elaborate `tryContextIntrinsicCall`), lowered to a stack `hzstd_context_t __hz_ctxN`, zero allocations. `clone` copies the current context after evaluating the body expression; `init` takes any value.
- ABI: every Haze fn is `R f(hzstd_context_t *__hz_ctx, [this], ...)`; extern C fns are unchanged. `extern C (params) -> R` (only `->`) is the only C-callable fn type and is never added automatically. fn to cptr only via `as cptr` (H7224), cptr to fn is H7223. A function type's return type takes a union, `extern C` too (since 2026-11-11, as in TypeScript): `extern C () -> A | B` returns `A | B`; a union of the function and B is `(extern C () -> A) | B`.
- C enters Haze only via an `extern C` fn with a Haze body calling `Context.init(ctx, () => ...)`; C receives contexts by value. Models: `rx.Thunk` + `rx.__hz_rx_run_thunk` (`reactive.hz`), the ui_layout `hzui_*` entries, SDL `haze*Dispatch(ctx, ...)`, wgpu (`ref Box<Context>` in userdata2), `single_instance`. `json.parse` rejects any type containing a Context.
- Tests: `testsuite/src/cases_context.hz`, `cases_extern_c_function_types.hz`, `cases_context_review.hz`; `tests/stdlib-paths/headless` runs in `scripts/run-tests.sh`; wgpu/GL/single_instance parts via the opt-in `scripts/run-stdlib-path-tests.sh`.
- Trap: a dev run of quick-todo rewrites `~/.config/autostart/quick-todo.desktop` and its hotkey request starts portal processes that draw on the real display; run it only sandboxed (`unshare -U -n --map-current-user`, `dbus-run-session`, scratch XDG_*_HOME).
