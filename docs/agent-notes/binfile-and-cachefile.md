# binfile and CacheFile

`stdlib/binfile`: the typed binary container (a root value and chunks, read by field name, CRC-32C) and `CacheFile<T>`, a deep reactive value kept in such a file and shared between processes.

Verified 2026-11-11 against d341d7f0 plus the uncommitted startup work (stdlib/binfile/tests).

- Container (`stdlib/binfile/src/binfile.hz`, its header comment is the byte layout): `binfile.write<Root, Chunk>(format, root, chunks)`, `binfile.read<Root, Chunk>(format, data, { views })`, `binfile.isFormat(format, head)`. A `binfile.Format` is the 8-byte magic (as Bytes) and a name for messages ("made by a newer Haze Notes"). Errors `binfile.Error { problem, message, offset, chunk, path }`, `binfile.Problem` NotThisFormat / Newer / Damaged / Incompatible. Fields skipped by the format carry `[[binfile.skip]]`. Was haze-notes' hznote.hz container until 2026-11-11; .hznote is now this with its own magic ([[hznote-format]]).
- `views: true`: every str and Bytes read is a view of `data` (BinaryReader.readView), no copy; `data` stays alive as long as any of them. For files read whole and kept (caches), not for files of which little is kept.
- Trap: a module's interface (`__haze__/<module>/build/import.hz`) carries exported functions and types but no constants, and generic code is re-elaborated in the importer, so a generic that names a module constant fails there with H3002. binfile's constants are `export fn kindStruct(): int` etc. for that reason.
- Trap: a struct with no fields makes `traverse.readStruct` emit `createStaticArray<bool, 0>` as `T array = {0}` (invalid C). `binfile.NoChunks` (the chunk type of a cache) has one `u8` field for that reason.
- `CacheFile<T>` (`stdlib/binfile/src/cachefile.hz`; use `from binfile import CacheFile`): `data` is `rx.reactive<T>`. One computed per top-level field reads all of it (`trackField` = `rx.traverse`); `rx.isDirty` on it is "changed here", so a write at any depth marks its top-level field. `flush()` (call every frame; free while nothing changed) writes once the value has settled (`CacheFileOptions.settleSeconds` 0.25, `maxDelaySeconds` 2.0); `flushNow()` / `close()` write at once, waiting for the lock up to `lockWaitSeconds`.
- A write: `fs.tryLockFile("<file>.lock")` (busy: tried at the next flush; [[file-locks]]), read the file, take every field this instance has not changed from it (`rx.assign`, cells kept, see [[cachefile-reload-swaps-field-cells]]), write `CacheRecord<T> { writerProcess, writerStarted, writerInstance, generation, value }` with `fs.replaceBinary`, unlock. Generation = file's + 1 under the lock, so unique per file. Different fields changed by two instances both survive; the same field: the later write wins. The fixed `<file>.saving` temp name of replaceBinary is safe only because writers hold the lock.
- Reading needs no lock (atomic replace). A damaged or incompatible file reads as T's defaults (one line on stdout) and is replaced by the next write. No file is written before something changes.
- Other instances' writes arrive through `fs.watch` (stat polling, `fs.pollEvents`): own write = stat equal to the one taken right after writing, else the record's writer and generation; anything else is taken in like above.
- `rx.toPlain<P, V>(value)` (core `reactive.hz`) reads a deep reactive back as its plain value (value structs only); the write uses it.
- Tests: `scripts/run-stdlib-test.sh stdlib/binfile/tests/binfile-tests.hz binfile crc32c` (versions, plain copies, formats, views) and `.../cachefile-tests.hz` (nested writes, merge, settle, busy lock, damage, own writes, a second process). A mutant that skips taking the other instance's fields fails two checks.
- Users: haze-notes `app.hzcache` (global), `<vault>/.hznotes/vault.hzcache` and `index.hzcache` ([[haze-notes-ui-architecture]]). codeeditor and others still use `json.CacheFile`.
