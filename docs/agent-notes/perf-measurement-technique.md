# Finding freezes and hitches in a Haze GUI app

A measurement recipe: isolated scripted bench build, GC stats, the built-in sampling profiler, burst analysis of the trace, and compiler build-time benchmarking.

Verified 2026-11-04 against d35a505e. (env vars and flags checked in src/main.ts and ModuleCompiler.ts; procedure details come from 2026-10 sessions and were not re-run)

1. **Isolated build**: a scratch directory inside the repo (e.g. `<repo>/.hnbuild_tmp/`) with a `compiler` symlink, copied `__haze__/haze-parser/{.source-hash,bin/haze-parser}`, a haze.toml with absolute stdlib paths, and sources copied in the project's `ls -U` order (see [[order-dependent-struct-method-elaboration]]). Build with `bun run ../src/main.ts build --dir haze-notes --quiet` from there, never from the repo root ([[shared-haze-workspace-rebuild-pingpong]]). Point the app's cache paths at a scratch data directory with a COPY of the real document, since autosave writes it.
2. **Instrumentation as a re-appliable patch**: a script that copies fresh sources and string-patches timers in (per-frame dt/work, document render, tiles drawn, tessellation count/ms, persist ms, ui vs present). A scripted driver from `ui.onFrame` runs zoom/pan phases relative to "document open", then `requestClose()`.
3. **Run** the built binary (e.g. `SDL_VIDEODRIVER=x11 timeout 150 ./__haze__/haze-notes/bin/haze-notes`). `GC_PRINT_STATS=1` prints Boehm "Complete collection took N ms" and "In-use heap: (X KiB pointers + Y KiB other)"; "pointers" is what every collection scans.
4. **Sampling profile**: `HAZE_PROFILE=1 HAZE_PROFILE_MEMORY=0 HAZE_PROFILE_SAMPLING_RATE=4000 HAZE_PROFILE_OUT=...` (set from `--profile*` options in src/main.ts). The trace is Chrome JSON (ProfileChunk cpuProfile nodes/samples/timeDeltas). Samples are on-CPU only and deep stacks are truncated from the TOP (outer frames vanish), so group samples into bursts by >3 ms gaps: a long burst is a CPU-bound hitch, a long frame with few samples is blocking (e.g. swapchain acquire). Print `time.now() - processStart` in bench lines to line frames up with trace time.
5. **Passive recorder** on a release build: poll `/proc/PID/task/PID/syscall` every 4 ms to log stretches >=120 ms on CPU or in one non-idle syscall, next to `perf record -e cpu_core/cycles/u,cpu_atom/cycles/u -F 2000 --call-graph lbr -k CLOCK_MONOTONIC -p PID` (hybrid CPU: name both PMUs). The installed binary is stripped, but a `--release --no-strip` build of the same tree has identical .text, so its `nm` symbolizes the recorded addresses.
6. **Compiler build-time bench**: reflink-copy a project's `__haze__` into a scratch dir, run `bun run <compiler>/src/main.ts build --dir <abs project> --timing-graph` (see [[timing-graph-and-main-thread-lock]]). Force a full rebuild without re-running generators by rewriting `"compilerKey"` in `__haze__/build-cache/*.json` to a bogus value (`--full-rebuild` also re-runs cmake/cargo). Point the bench's `compiler` symlink at a frozen worktree, not a live checkout (another editor changing compiler/haze-parser/src mid-run makes the parser stamp stale and every build die), and never alternate two compilers in one workspace (every run becomes a full rebuild). Use instruction counts (`perf stat -e cpu_core/instructions/u`) for A/B when the machine is loaded.
